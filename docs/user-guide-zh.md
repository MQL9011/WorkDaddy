# WorkDaddy 使用指南

面向不熟悉终端、也面向想把自制技能分发给团队的用户。

---

## 1. 安装与首次启动

WorkDaddy 本身不内置 omp（oh-my-pi）——它是一个独立的开源命令行智能体，
体积不小（macOS arm64 单文件约 108MB），塞进安装包会让下载变得没有必要地大。
第一次打开 WorkDaddy 时，如果本机还没有 omp，会自动弹出首启向导，依次完成：

1. **欢迎页** — 点「Get started」开始。
2. **检测 / 安装 omp** — 如果已经装过 omp（在 `PATH` 里，或者你自己配置过路径），
   这一步会直接显示检测到的版本，点「Continue」跳过。如果没有，点「Download and
   install」，WorkDaddy 会向 omp 官方 GitHub Releases 请求最新版本、下载对应你
   电脑平台的二进制、用 omp 官方发布的 `SHA256SUMS.txt` 逐字节核对哈希，确认无误
   后才会安装。如果校验失败，WorkDaddy 会直接丢弃下载的文件，绝不会替你运行一个
   没验证过的程序。
   - 如果下载失败（网络问题、GitHub 不可达等），向导会给出手动安装的命令作为备选：
     ```bash
     curl -fsSL https://omp.sh/install | sh
     ```
     或者用 Homebrew：`brew install can1357/tap/omp`。装好之后回到向导点「Try again」。
3. **选择工作目录** — 用系统原生的文件夹选择器，挑一个你想让 omp 处理的本地文件夹
   （代码仓库或任意项目目录）。WorkDaddy 只会访问你明确添加过的文件夹。
4. **审批模式** — 决定 omp 在没有确认的情况下能做多少事：
   - **Always ask**（默认，推荐先用这个）：每次改文件、每次执行命令前都会问你。
   - **Ask before running commands**：可以自己改文件，但执行终端命令前还是会问。
   - **Never ask**：完全自主，不再确认。只有你完全信任要交给它做的任务时才选这个。
   - 这个选项之后随时可以在「设置 → Agent」里改。
5. **登录引导** — omp 的登录凭据完全由 omp 自己的 CLI 管理（存在 `~/.omp/agent/agent.db`
   里），**WorkDaddy 不会看到、不会存储、也不会转发你的任何凭据**。这一步会直接帮你
   打开内置终端面板，你只需要：
   1. 输入 `omp` 回车，进入 omp 的交互界面；
   2. 输入 `/login`，跟着提示完成登录（支持多种模型服务商，包括各家的 OAuth 登录）。
   完成后关掉终端标签页即可，WorkDaddy 会自动识别登录状态。

任何一步都可以点右上角「Skip setup」跳过，之后在「设置」页里手动完成对应配置。

## 2. 日常使用

### 2.1 发起对话

侧栏点「New session」（或 `⌘N` / `Ctrl+N`）开始一轮新对话。输入框下方可以：

- 点「＋」附加图片。
- 选择模型和思考强度（如果当前模型支持）。
- 用权限 chip 临时切换这次会话的审批模式。
- 输入框下方的状态条会显示本轮用了多少轮、耗时、token 数。

### 2.2 技能库

侧栏底部「技能」入口（与「设置」并列）打开技能库，这是 WorkDaddy 相对纯命令行
最大的差异点——**技能在命令行里完全是黑盒，装了什么、有没有冲突，用户看不见**。

- 技能按来源分组：Project（当前项目内 `.omp/skills`）→ Personal（`~/.omp/skills`）→
  Bundled（应用内置能力）→ System。
- 搜索框 + 来源筛选可以快速定位。
- 点开任意一条技能可以看到：frontmatter 字段（描述、`globs`、`alwaysApply`、
  `disable-model-invocation`）、SKILL.md 正文渲染、同目录下的文件清单，还有一个
  **非递归发现校验器**——如果某个子目录自己也放了一个 `SKILL.md`，会被明确标红提醒：
  omp 的目录扫描只认 `skills/<name>/SKILL.md` 这一层，更深一层的定义会被静默忽略，
  这是一个容易踩的坑，命令行里完全看不出来。
- **同名冲突**：如果两处技能声明了一样的 `name`，两条记录都会出现，并且都带一个
  「Duplicate name」提示——omp 本身没有"谁生效"的仲裁机制，WorkDaddy 不会假装
  知道答案，只会诚实地告诉你"这里有冲突，你需要自己看一下"。
- 对话过程中，如果某一轮回复读取的文件恰好匹配到已知技能的路径，回复顶部会出现一枚
  「Possibly used `<技能名>`」的小徽章。这是路径匹配的**尽力而为**的提示，不是精确
  信号——omp 本身不会告诉桌面端"我刚刚用了哪个技能"，所以徽章只说"可能用到"，不说
  "确实用到"。

技能的安装、启用/禁用走「功能」页（Capabilities），不在技能库里重复一套——技能库
本身是纯浏览视图；单个技能文件在 omp 里也没有独立的启停开关，只有包含它的插件包
（package）能整体启用/禁用。

### 2.3 项目与会话

- 「项目」页管理已添加的文件夹，可以固定、移除、在系统文件管理器里打开。
- 「动态」页汇总所有需要关注的会话（等待输入、失败、有新消息）。
- 侧栏搜索（`⌘F`）可以按项目名、会话标题、分支名过滤。

## 3. 常见问题 FAQ

**Q: WorkDaddy 会不会看到我的 API Key 或登录凭据？**
不会。所有模型服务商的凭据都由 omp 自己的 CLI 管理，存在 `~/.omp/agent/agent.db`，
WorkDaddy 从不读取、解析或转发这个文件。设置页里的「Providers」开关只是控制
"这个服务商在 WorkDaddy 界面里显不显示"，不会改动 omp 自己的凭据配置。

**Q: 首启向导下载的 omp 是从哪里来的？安全吗？**
直接从 omp 官方 GitHub 仓库（`can1357/oh-my-pi`）的 Releases 下载，源地址写死在
WorkDaddy 代码里、不可配置，避免"下载并运行任意地址内容"的风险。下载后会用
omp 官方随每个版本发布的 `SHA256SUMS.txt` 逐字节核对哈希，任何不匹配都会导致
下载被直接丢弃，绝不会安装。

**Q: 我已经用命令行装过 omp 了，还需要走一遍向导吗？**
不需要。向导会自动检测 `PATH` 和常见安装目录，如果已经找到可用的 omp，「检测 / 安装」
这一步会直接显示版本号，点「Continue」跳过即可。

**Q: 审批模式选错了怎么办？**
「设置 → Agent → Approval mode」随时可以改，不需要重新走向导。

**Q: 技能库里的「Duplicate name」是不是意味着出问题了？**
不一定，但值得去看一眼两个文件分别是什么。这通常发生在：你同时把一个技能放进了
个人技能目录（`~/.omp/skills`）和某个项目的项目技能目录（`.omp/skills`），或者
不小心复制粘贴了两份。omp 不会替你决定"用哪个"，所以两个都会加载/暴露给模型，
可能导致行为和你预期的不一致。

**Q: WorkDaddy 支持 Pi 或 Prime Agent 后端吗？**
不支持。WorkDaddy 是 [gooey-pi](https://github.com/am-will/gooey-pi) 的裁剪 fork，
专注 omp 单一后端；如果需要多后端支持，请使用上游项目。详见 [`NOTICE.md`](../NOTICE.md)。

**Q: 在哪里报告 bug 或提建议？**
提交 [GitHub Issue](https://github.com/MQL9011/WorkDaddy/issues)。安全相关的问题
请遵循 [`.github/SECURITY.md`](../.github/SECURITY.md) 里的流程，不要在公开 issue 里
直接贴敏感细节。
